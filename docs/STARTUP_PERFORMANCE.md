# Windows 啟動效能

PicView 的 Windows 桌面版改以 PyInstaller `onedir` 打包，並將整個 `PicView` 資料夾放入 ZIP。使用者只需解壓一次；啟動時不再重複解壓單檔 EXE 的依賴。macOS 的 App bundle 維持原有形式。

## 同機量測

2026-11-08 在同一台 Windows 電腦上，以已發布的 v0.1.9 單檔 EXE 與本次資料夾版交錯啟動。量測從啟動 EXE 到 PicView 主視窗出現，使用 `scripts/measure_startup.ps1`，每次量測前關閉 PicView。

| 形式 | 三次主視窗顯示時間 | 中位數 |
| --- | --- | --- |
| 單檔 EXE | 10.82、6.58、6.72 秒 | 6.72 秒 |
| 資料夾版 | 4.44、3.68、2.21 秒 | 3.68 秒 |

資料夾版在這三次樣本中的中位數快約 3.04 秒。樣本數少，且受到檔案快取、防毒掃描、系統負載及已儲存的資料夾狀態影響，不能視為其他電腦的保證值。此指標是「主視窗出現」，不代表第一張圖片與所有縮圖都已完成載入。

量測指令（先關閉所有 PicView 視窗）：

```powershell
./scripts/measure_startup.ps1 -OldExe ./build/baseline/PicView-0.1.9-windows-x64.exe -NewExe ./dist/desktop/PicView/PicView.exe -Runs 5
```

建置流程會先對資料夾版執行封裝測試，再驗證 ZIP 完整性，並從解壓後的 ZIP 再執行一次封裝測試。已有視窗時，輕量入口會先以 Qt Core 與 Qt Network 的本機連線轉交多個檔案路徑，再載入圖片與 Qt Widgets；轉交失敗才走完整啟動。正常啟動仍保留原本的轉交檢查，以涵蓋接收端剛就緒的時機。

## 已有視窗時的轉交

保持新資料夾版 PicView 視窗開啟，使用一個不存在的圖片路徑呼叫第二個 EXE，計時直到第二個行程退出。這避免重複開啟測試資料夾，但仍經過接收端的確認流程。2026-11-08 同機交錯量測：

| 形式 | 三次轉交並退出時間 | 中位數 |
| --- | --- | --- |
| v0.1.9 單檔版與原有轉交流程 | 5.20、7.96、6.89 秒 | 6.89 秒 |
| 資料夾版與輕量入口 | 0.57、0.60、0.58 秒 | 0.58 秒 |

此對照同時改變封裝形式與轉交時機，無法把兩者的效益分開。量測也不代表有真實圖片時的解碼完成時間。
